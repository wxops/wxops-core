# Release Notes — v0.2.4

## Highlights

Bug-fix release for `XTenantDatabase` dynamic tier resolution. The shared
cluster discovery pipeline introduced in v0.2.2 had three issues that
prevented `tier: shared` from working on real clusters — all three are now
fixed.

## Bug Fixes

### `XTenantDatabase` (`package/tenant-database/`)

- **Extra resources read from wrong location** — `function-extra-resources`
  stores fetched resources in the pipeline context at
  `ctx["apiextensions.crossplane.io/extra-resources"]`, not in
  `option("params").extraResources`. The KCL was reading the wrong field,
  resulting in an empty cluster pool on every render. Fixed to read from the
  pipeline context.

- **Resource unwrapping mismatch** — resources in the pipeline context are
  stored directly as `{apiVersion, kind, metadata, spec, status}`, not
  wrapped in `{resource: ...}` as assumed. The `r.resource` accessor
  returned `Undefined` for every cluster, producing a list of empty entries.
  Fixed by removing the `.resource` unwrapping.

- **`_get` helper crashed on Undefined dicts** — the `_get(d, k, default)`
  helper used `k in d`, which raises `TypeError: argument of type
  'UndefinedType' is not iterable` when `d` itself is `Undefined` (not just
  a missing key). This affects resources from the pipeline context where
  nested fields like `status` can be `Undefined`. Fixed with `d or {}`
  guard. All `"key" in obj` patterns on pipeline resources replaced with
  `_get(obj, "key", default)`.

- **Empty `matchLabels` silently skipped** — `function-extra-resources`
  v0.3.0 skips selectors with no `matchLabels` entries, then fails with
  `cannot find expected extra resource`. Both selectors (`allClusters`,
  `existingDatabases`) now include explicit `matchLabels`.

- **Crossplane dxr labels not applied** — the composite reconciler writes
  `status` from dxr updates but ignores `metadata.labels`. Shared cluster
  discovery now uses a user-applied label (`wxops.cloud/managed-by`) instead
  of dxr-set labels, and filters by `status.shared` / `status.environment`
  in KCL (with fallback to `spec.parameters` for clusters that haven't
  reconciled status yet).

## Upgrade notes

- **Discovery labels are now required** — Crossplane's composite reconciler
  writes `status` from dxr updates but **ignores `metadata.labels`**, so
  discovery labels must be in the XR manifest (applied by user or GitOps).
  Add to every existing XR:

  ```bash
  # Platform clusters — required for tier: shared pool discovery
  kubectl label xplatformdatabasecluster <name> \
    wxops.cloud/managed-by=platform-database-clusters

  # Tenant databases — required for load balancing and collision detection
  kubectl label xtenantdatabase <name> \
    wxops.cloud/tenant-database=true
  ```

  Include these labels in all XR manifests going forward (see updated
  examples). Without them, `function-extra-resources` returns 0 results
  for that resource type.

  | Resource | Required label | Purpose |
  |---|---|---|
  | `XPlatformDatabaseCluster` | `wxops.cloud/managed-by: platform-database-clusters` | Discovered for `tier: shared` pool |
  | `XTenantDatabase` | `wxops.cloud/tenant-database: "true"` | Tenant counting + `dbName` collision check |

- **Deploy order**: apply updated `platform-database-clusters` package first
  (so clusters write status fields), then apply updated `tenant-database`
  package.

- No schema changes — existing XR specs are fully backward compatible.
