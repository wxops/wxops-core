## Highlights

**`release-2026-09-16` is the first date-named release, and the OSS-readiness release.** Every
package is rebuilt and published under a new home, `ghcr.io/wxops/wxops-core/<pkg>`, replacing the
semver tags (`v0.1.0` … `v0.4.0`) this project used through `v0.4.0`. Compatibility now lives in the
XRD API version, not the release name — see [`release-notes/README.md`](https://github.com/wxops/wxops-core/tree/main/release-notes/README.md).

Alongside the release mechanics, this is the release that gets the repository ready for outside
contributors: a licence, a code of conduct, a private security-disclosure channel, a README written
for someone with no platform context, and documentation reorganised into sections a newcomer can
actually navigate.

---

### Registry and package naming

Packages moved twice in this release, settling on the final shape:

1. `platform-wxops-<pkg>` → `wxops-core-<pkg>`, matching the repo name.
2. `ghcr.io/wxops/wxops-core-<pkg>` → `ghcr.io/wxops/wxops-core/<pkg>` — the project identity moved
   from a name prefix into the registry path itself, so every package name is now just its own name
   (`gitea-user`, `tenant-app`, and so on).

Neither name was ever published before this release, so there is nothing for an existing consumer to
migrate — this is the name every package ships under from here on.

### Package channels — a label, not a pipeline

Every `package/<pkg>/composition.yaml` now carries `metadata.labels.channel: stable`, committed in
Git; `make install-dev` overrides it to `channel: nightly` via a Kustomize `labels:` transformer, no
build step involved. An XR opts into a channel with two native Crossplane fields —
`compositionRevisionSelector.matchLabels` + `compositionUpdatePolicy: Automatic` to auto-track a
channel, or `compositionUpdatePolicy: Manual` with an explicit `compositionRevisionRef` to never
auto-move at all (recommended for production XRs). See
[`docs/development/releasing.md#channels`](https://github.com/wxops/wxops-core/tree/main/docs/development/releasing.md#channels).

This replaces an earlier, considerably heavier design — Kyverno admission policies, a `make promote`
soak-check pipeline, a phased kind-rehearsal build-out — that was designed and then deliberately
rejected as too complex for a single-maintainer project to operate or explain. See
[ADR-001](https://github.com/wxops/wxops-core/tree/main/docs/adr/001-package-channel-label.md), the
first entry in a new `docs/adr/` decision-record convention this release also introduces.

### Project infrastructure

- **`LICENSE`** (Apache-2.0) and **`NOTICE`**, **`CODE_OF_CONDUCT.md`** (Contributor Covenant v2.1),
  and **`SECURITY.md`** — private disclosure via GitHub Security Advisories.
- **README.md rewritten** for a reader with no platform context: what problem this solves, ahead of
  the packages table, plus a structural diagram of how a Configuration package becomes a running
  composite resource.
- **GitHub is now primary**; the Gitea instance is archived (frozen, read-only, kept for internal
  reference and on-request demos).

### Documentation reorganised

`docs/` moved from a flat file list into six sections behind one hub,
[`docs/README.md`](https://github.com/wxops/wxops-core/tree/main/docs/README.md), which also carries
a development matrix (every package, core idea and delivery mechanism, its state and what's next):

- **`docs/learn/`** (new) — four short pages that teach Crossplane, the inline-HCL Terraform pattern,
  and this repo's KCL idioms against real files in the repo, ending with a guided first change.
  Prerequisite reading for `docs/development/`, not part of it.
- **`docs/adr/`** (new) — architecture decision records, introduced by this release's own channel
  decision (see above).
- **`docs/api-reference/`** — the reconcile loop from a user's side, one page per Kind, the status
  contract.
- **`docs/core-ideas/`** — gained `knowledge-architecture.md`, `multi-cluster-connectivity.md`,
  `multi-cluster-proposal.md`, and `multi-cluster-scale.md`, plus a substantially expanded
  `observability.md` and new `portal-integration.md`.
- **`docs/user-guide/`** and **`docs/development/`** — setup, app onboarding, the development guide,
  and releasing, each now a standalone page instead of a section of a longer file.

### Testing

`tests/lib/releases.py` and a set of `_api_compat` fixture pairs (`content-changed`,
`default-changed`, `enum-narrowed`, `optional-added`, `property-removed`, `required-added`,
`required-in-new-object`, `resource-renamed`, `selector-changed`, `status-field-removed`,
`type-changed`) self-test the `safe`/`careful`/`breaking` classifier itself — each fixture pins the
tier `test-api-compat` must produce, so the classifier's own correctness is a golden test, not an
assumption.

## Upgrade notes

No action required. Nothing was published under either of this release's two intermediate naming
schemes (`platform-wxops-<pkg>` or `ghcr.io/wxops/wxops-core-<pkg>`) before this release, so there is
no prior consumer to migrate.
