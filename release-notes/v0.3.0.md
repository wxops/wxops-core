# Release Notes

## Highlights

v0.3.0 ships **Darlane** — a full rework of the `XTenantApp` debug-twin — and
backports the **Crossplane v2 XR readiness fix** (`krm.kcl.dev/ready`) to every
KCL package in the platform.

**Darlane** replaces the earlier `devSpace` concept with a first-class developer
workspace inside the tenant app scaffold. It covers everything from a usable debug
pod (independent resources, env layering, security context overrides) through
fileSync, A/B traffic splitting with sticky sessions, cert-manager TLS
auto-provisioning, and multi-source volumes — all driven by the same `XTenantApp`
claim.

The readiness patch fixes a long-standing bug where Crossplane v2.3 +
function-kcl v0.12.1 always reported `type: Ready` as `False` on composed Objects.
Every package now annotates observed-ready resources with `krm.kcl.dev/ready:
"True"` so the XR composite condition reflects real cluster state.

### `XTenantApp` — Darlane developer workspace

**Ingress rework — Traefik `IngressRoute` (replaces standard `Ingress`)**

- All apps with `ingress.enabled: true` now receive a Traefik `IngressRoute` (CRD
  `traefik.io/v1alpha1`) instead of a standard Kubernetes `Ingress`. No field changes
  required — existing XRs migrate in-place on reconcile.
- `IngressRoute` supports both `kind: Service` (plain routing) and `kind:
  TraefikService` (weighted split) as backends, enabling zero-downtime A/B weight
  switching: the same Object exists throughout; only `spec.routes[].services` changes.
- `ingress.className` and `ingress.pathType` are no-ops kept for schema compatibility —
  the `IngressRoute` spec does not use them.
- SSO (`ingress.auth.enabled`) now wires Traefik `Middleware` CRD references in
  `spec.routes[].middlewares` rather than Ingress annotations.

**cert-manager TLS auto-provisioning**

- New field `ingress.tls.clusterIssuer` — when set (and `tls.enabled: true`), the
  composition emits a `cert-manager.io/v1 Certificate` CR pointing at the named
  `ClusterIssuer`. cert-manager writes the TLS Secret into `tls.secretName`; the
  `IngressRoute` references the same name.
- Without `clusterIssuer`, `tls.secretName` must already exist (unchanged from before).
- provider-kubernetes RBAC updated with `cert-manager.io/certificates` rule.

**Darlane — fileSync**

- `darlane.fileSync.enabled: true` mounts a writable `emptyDir` volume at `mountPath`
  (default `/app`) on top of the read-only rootfs. Works with `readOnlyRootFilesystem:
  true`.
- `darlane.fileSync.initFromImage: true` (default) — an `initContainer` pre-populates
  the volume from the image using `cp -rp <mountPath>/. /darlane-sync/`, including
  dotfiles, so the pod starts with a full working tree ready for live sync.
- Sync tools (`mutagen`, `kubectl cp`) push deltas; hot-reload commands (`--reload`,
  `nodemon`, `air`) pick them up without pod restarts.

**Darlane — A/B traffic splitting**

- `darlane.trafficWeight` (0–100) emits a `ClusterIP` Service for the darlane pod and a
  Traefik `TraefikService` weighted split (`<appName>-weighted`). The `IngressRoute`
  backend switches to the `TraefikService` when `trafficWeight > 0`.
- `darlane.stickySession` — per-session cookie pinning on the weighted split
  (`cookieName`, `secure`, `sameSite` configurable).
- `darlane.telemetryPort` — emits a dedicated `ClusterIP` Service named
  `<appName>-darlane-telemetry` for OTEL collector / Prometheus scraping. Combine with
  `trafficWeight` for side-by-side A/B observability.

**Darlane — safety & access control**

- `darlane.productionOverride` — required when `environment: prod`; double opt-in is
  visible in XR diffs and PRs.
- `darlane.ttl` — `wxops.cloud/darlane-ttl` annotation on the dev Deployment.
  Enforcement via the Kyverno `ClusterCleanupPolicy` in `providers/policies/`.
- `darlane.rbac` — emits a scoped `Role`/`RoleBinding` granting `pods/exec`,
  `pods/portforward`, `pods/log`, and scale on `<appName>-darlane` only. Subjects
  configured via `darlane.rbac.subjects`.
- `darlane.serviceAccount` — dedicated SA for the darlane pod with optional workload
  identity annotations (IRSA / GCP WI).

**Volume expansion — ConfigMap and Secret sources**

- `volumes[]` and `darlane.volumes[]` now accept three source types, discriminated by
  which field is set:
  - `claimName` → `PersistentVolumeClaim` (unchanged; main `volumes[]` still supports
    `create: true`)
  - `configMapName` → existing `ConfigMap`
  - `secretName` → existing `Secret`
- Optional `items[]` key-to-path projections for ConfigMap and Secret volumes: only the
  listed keys are mounted at the specified relative paths inside `mountPath`.
- `claimName` is no longer required in the XRD schema; existing PVC-backed volumes are
  unaffected.

**provider-kubernetes RBAC**

- Added `traefik.io` rule: `traefikservices`, `ingressroutes`.
- Added `cert-manager.io` rule: `certificates`.
- Retained `networking.k8s.io/ingresses` for migration (existing clusters may still hold
  `Ingress` objects from the previous composition revision).

### KCL readiness fix — all packages

`platform-database-clusters` and `tenant-database` receive the same `_isReady` /
`krm.kcl.dev/ready` machinery already applied to `tenant-app`:

- Each `Object`'s metadata annotations include `krm.kcl.dev/ready: "True"` whenever
  the observed composed resource reports a `Ready=True` condition.
- This instructs `function-kcl` v0.12.1 to emit `READY_TRUE` for the resource, fixing
  the Crossplane v2.3 bug where the native `type: Ready` composite condition is always
  `False` regardless of actual cluster state.
- `_ocds` is read from `option("params").ocds` (keyed by Object name, not
  `composition-resource-name`). The boolean `True` annotation form is rejected by
  function-kcl v0.12.1 — the string `"True"` is required.

Affected composed resources:
- `platform-database-clusters`: `cnpg-cluster`, `cnpg-rw-pooler`, `cnpg-ro-pooler`,
  `cnpg-scheduled-backup`, `superuser-push-secret`, `app-push-secret`, and all
  `managed-role-*` Objects.
- `tenant-database`: `tenant-pwd-gen`, `tenant-conn-bundle`, `tenant-sql-role`,
  `cnpg-database`, `tenant-role-db-usage`, `tenant-conn-role-usage`.

## Upgrade notes

**IngressRoute migration**

All existing `XTenantApp` resources with `ingress.enabled: true` will have their
`Ingress` object replaced by an `IngressRoute` on the next reconcile after upgrading.
Traefik picks up the new `IngressRoute` immediately — no DNS or TLS changes required.
The old `Ingress` object is garbage-collected by Crossplane.

If any external tooling (monitoring, GitOps diff alerts) watches for `Ingress` objects
by label, update those selectors to also match `IngressRoute`.

**cert-manager TLS (opt-in)**

No action required unless you want auto-provisioned certificates. To enable, add
`ingress.tls.clusterIssuer: <issuer-name>` to an existing XR. cert-manager and the
named `ClusterIssuer` must exist in-cluster first.

**provider-kubernetes RBAC**

Apply the updated `providers/rbac-provider-kubernetes.yaml` before or alongside
upgrading the `tenant-app` composition:

```bash
kubectl apply -f providers/rbac-provider-kubernetes.yaml
```

Without this, provider-kubernetes will fail to create `IngressRoute`,
`TraefikService`, or `Certificate` objects with a 403 Forbidden error.

**Darlane — existing `devSpace` users**

The `devSpace` parameter key has been renamed to `darlane`. Update any existing XR
claims:

```yaml
# Before
spec.parameters.devSpace.enabled: true

# After
spec.parameters.darlane.enabled: true
```

All sub-fields follow the same rename. The old `devSpace` key is no longer recognized.

**KCL readiness fix**

No action required. The fix is automatically applied on the next reconcile of any
existing `XPlatformDatabaseCluster` or `XTenantDatabase` claim. XR `Ready` conditions
will start reporting `True` correctly once all composed resources are observed as ready.
