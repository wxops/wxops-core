# Release Notes — v0.2.1

## Highlights

Patch fix for `ingress.auth.enabled` on `XTenantApp`: the SSO middleware
reference now uses Traefik's cross-namespace convention
(`kube-system-<name>@kubernetescrd`) pointing to the `auth-errors` and
`forward-auth-redirect` `Middleware` CRDs in `kube-system`, replacing the
previous same-namespace reference that required Kyverno to mirror the CRDs
into each tenant namespace.

## Changed

### `XTenantApp` (`package/tenant-app/`)

- `ingress.auth.enabled` — middleware annotation value changed from
  `auth-errors@kubernetescrd,forward-auth-redirect@kubernetescrd` (same-
  namespace, required Kyverno mirror) to
  `kube-system-auth-errors@kubernetescrd,kube-system-forward-auth-redirect@kubernetescrd`
  (cross-namespace reference to `kube-system`). No XRD schema change — the
  field is still a plain boolean.

## Upgrade notes

- **Traefik prerequisite**: `--providers.kubernetescrd.allowCrossNamespace=true`
  must be set on the Traefik deployment. Without it, Traefik silently ignores
  cross-namespace `Middleware` references and the auth chain does not run.
- **No Kyverno mirror needed**: the previous design required the platform to
  mirror `auth-errors`/`forward-auth-redirect` into every tenant namespace via
  Kyverno `generate`. That is no longer required — the CRDs only need to exist
  in `kube-system`.
- **Existing claims**: any `XTenantApp` with `ingress.auth.enabled: true` will
  have its `Ingress` annotation updated on the next reconcile. Traffic is not
  interrupted, but Traefik will re-evaluate the middleware chain using the new
  cross-namespace reference.

## Known issues

None.
