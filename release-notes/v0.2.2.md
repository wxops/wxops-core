# Release Notes — v0.2.2

## Highlights

The database core gets **dynamic tier resolution** — `XTenantDatabase` no
longer relies on a hardcoded cluster map. Shared clusters are now discovered
at render time via label selector, and a new `dedicated` tier lets tenants
spin up a fully isolated single-database cluster without leaving the
self-service API.

`XPlatformDatabaseCluster` gains a `shared` toggle that makes a cluster
visible to the tenant pool. Platform admins mark clusters as shared, and
`XTenantDatabase` automatically load-balances new databases across them —
picking the least-loaded cluster and preventing `dbName` collisions. Adding
capacity to the shared pool is now a one-field change on a cluster XR,
no KCL edits or package rebuilds required.

The Vault credential path is restructured to properly namespace
multi-database tenants.

## Changed

### `XPlatformDatabaseCluster` (`package/platform-database-clusters/` — v0.2.0)

- **`shared`** (boolean, default `false`) — marks this cluster as part of
  the shared multi-tenant pool. Sets the `wxops.cloud/shared-cluster` label
  on the XR for discovery by `XTenantDatabase`.
- **`status`** subresource — exposes `clusterName`, `namespace`, `shared`
  for consumption by `function-extra-resources` selectors.

### `XTenantDatabase` (`package/tenant-database/` — v0.2.0)

- **`tier`** is now an enum (`shared`, `dedicated`):
  - `shared` (default) — auto-assigns to the least-loaded
    `XPlatformDatabaseCluster` with `shared: true`. Counts existing tenant
    databases per cluster and picks the one with the fewest. Asserts on
    `dbName` collision within the selected cluster.
  - `dedicated` — composes a child `XPlatformDatabaseCluster` inline
    (1 cluster = 1 database, fully isolated). Sized via the new
    `dedicatedCluster` parameters.
- **`dedicatedCluster`** — sizing parameters for `tier: dedicated`:
  `instances`, `storageSize`, `postgresVersion`, `enablePooler`, `namespace`.
- **Vault path restructured** — PushSecret now writes to
  `tenants/{owner}/databases/{dbName}/connection-creds` (was
  `tenant/{owner}/{dbName}/connection-creds`). The `databases/` level
  gives multi-database tenants a clean hierarchy.
- **Composition pipeline** — now a two-step pipeline:
  `function-extra-resources` (fetch shared clusters + existing databases) →
  `function-kcl` (render). The hardcoded `_clusterTierMap` is removed.
- Explicit `clusterRef`/`clusterNamespace` override still bypasses all
  tier logic — backward compatible.

### New provider

- `providers/function-extra-resources.yaml` —
  `crossplane-contrib/function-extra-resources:v0.4.0`.

## Upgrade notes

- **Install `function-extra-resources`** before deploying the updated
  packages:
  ```bash
  kubectl apply -f providers/function-extra-resources.yaml
  ```

- **Deploy `platform-database-clusters` first**, then label existing shared
  clusters:
  ```yaml
  # On your existing cluster-a XR:
  spec:
    parameters:
      shared: true
  ```
  The composition sets the `wxops.cloud/shared-cluster` label and writes
  status fields. `XTenantDatabase` won't discover any clusters until this
  is done.

- **Vault path change** (breaking) — existing PushSecrets will write to the
  new path (`tenants/{owner}/databases/{dbName}/connection-creds`) on the
  next reconcile. Downstream ExternalSecrets consuming the old path
  (`tenant/{owner}/{dbName}/connection-creds`) must be updated. Old Vault
  entries are NOT auto-deleted — clean up via Vault CLI after migration is
  confirmed.

- **Existing `clusterRef` XRs** are unaffected — explicit cluster references
  bypass tier resolution entirely.
